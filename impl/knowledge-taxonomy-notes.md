# Slice 10 implementation notes

Cites [slice plan](../docs/plan/10-knowledge-taxonomy/plan.md), [pinned ORC evidence](../raw/orc/manifest.md), [prior integration note](knowledge-extraction-migration-notes.md), and [Grain knowledge model](src/awp_v2/knowledge/event_model.clj).

Keep Grain knowledge commands, events, and review read models authoritative. Add a versioned AWP taxonomy declaration with deterministic category IDs, parent relationships, definitions, and legacy-kind mapping. Use ORC's custom ontology and relationship commands for a derived owner graph; do not initialize ORC's failure/success/problem static ontology for personal knowledge. Preserve review and category IDs in ORC provenance. The existing `sync-owner!` only projects accepted item concepts, the current owner facade filters them, and the bounded sheet writes unreviewed candidates to a separate owner/source ontology. Extend these seams for explicit category edges and reviewed subject relations without changing review authority.

Inspect ORC's pinned [evolutionary API](../raw/orc/evolutionary.clj), [builder](../raw/orc/evolutionary-builder.clj), and [queries](../raw/orc/queries.clj) before choosing a write path. The full text evolutionary builder has a known local timeout in [slice 08](knowledge-extraction-migration-notes.md); use a bounded behavior-tree LLM path for candidate proposal, and pin its model, prompt, source digest, and deadline. Never treat `skos:broader` output as accepted without a Grain owner relation decision. The ORC guide notes an unscoped graph-BFS path; scope every public query by tenant/owner ontology and intersect with current Grain state. Direct ORC APIs are internal, not owner endpoints. Rebuild ORC from Grain after correction/revocation; because ORC has no delete command in the current adapter, either use a fresh versioned ontology for current reads or prove filtering at every read entry point. Avoid describing a stale retained ORC concept as removed from storage.

Start with red acceptance tests named for every scenario. Add a separate model quality fixture and evaluator; deterministic tests can verify identities, exact quotes, replay, relation decisions, and isolation but cannot decide semantic correctness. The evaluator must load a reviewed corpus, precommitted thresholds, and pinned model/prompt/taxonomy versions and write a report. If unavailable, keep the gate open. Existing old-data reconciliation and public tailnet qualification remain independent.
