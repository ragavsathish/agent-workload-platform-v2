# Ticket 01: category hierarchy and version

Cites [slice plan](plan.md), [taxonomy rules](../../wiki/knowledge-taxonomy.md), [source categories](../../../raw/v1/knowledge-processor.mjs), and [source vocabulary](../../../raw/v1/knowledge-ontology.ttl).

Define stable identities and descriptions for journal kinds, assertion kinds, and profile fields with explicit parents. Keep no-assertion as a decision outcome. Map existing items to the first category version only when their recorded kind is provable. Unknown, conflicting, or retired categories remain inspectable and require a recorded mapping decision before current interpretation changes. The same source item cannot gain a new meaning merely because the hierarchy is revised.

Acceptance: [taxonomy-001](spec.feature), [taxonomy-002](spec.feature), and [taxonomy-003](spec.feature).
