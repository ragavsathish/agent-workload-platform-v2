# Slice 04 implementation boundary

Cites the [stack-free plan](../docs/plan/04-live-session-integration/plan.md), [source service entry point](../raw/v1/voice-agent-service.ts), [source owner edge](../raw/v1/edge-bot.py), and [source broker](../raw/v1/broker-http.py).

The build should retain Pipecat inside Voice Edge for SmallWebRTC, turn detection, speech transcription and playback, and RTVI presentation. Keep the browser `/api/pi-*` controls, broker `/v1/pi/*` forwarding, and Pi service `/v1/*` contract compatible. Grain is authoritative for CQRS selection, turn admission, task routing, and public projections. The Pi voice runtime remains the effect executor: Pi session context, tools, the persistent Gondolin voice VM, and remote task socket. Use a narrow production bridge at the Pi service boundary, not a second owner-facing session implementation.

The bridge must bind a Grain selected conversation ID to the Pi saved session manager before reporting selection success. Persist or reconcile that binding; do not infer it from last-modified history. For each accepted turn, pass the Grain turn ID, fixed destination, prompt, and system prompt to the Pi runtime. Translate Pi text and tool lifecycle events into Grain's safe observations, settle after Pi reports an outcome, and mark uncertainty on transport or effect ambiguity. A duplicate accepted turn ID returns the existing Grain decision and does not call Pi again. Keep task attachment in the remote socket runtime, with Grain recording the routing decision and releasing it on selection or voice disconnect. A restart cannot recover an old socket.

The current `awp-v2.session.api` driver callback is insufficient on its own: it has no production HTTP surface, no streamed completion channel, no Pi history binding, and no task socket synchronization. The build needs production adapter code on both sides and a process-level owner journey. The existing `fresh!` generates a UUID while Pi's manager may generate another; binding must resolve that mismatch explicitly. `submit!` currently admits an effect without returning its completion; public typed and streamed responses need an outcome observation path. The build should test and resolve these gaps before claiming live integration.

Verification uses real route handlers, Grain event store and projections, Pi session lifecycle, and task socket protocol. A deterministic protocol driver may replace only the external model, speech recognition, and synthesis edges. Run a fresh-process restart check and a live connection protocol test. A deployed smoke test is required before claiming the configured Pipecat service works on the target host.
