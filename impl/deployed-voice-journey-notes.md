## Current baseline

At `0328fbb`, the local gate exercises Grain decisions, a production Pi HTTP route and session manager, broker forwarding, task socket protocol, and Python edge import. It does not create a WebRTC peer, send audio through Pipecat, run MLX recognition or synthesis, boot the persistent Gondolin VM, or run the deployed task worker. No deployed qualification is asserted by this planning turn.

## Build topology

The retained edge runs `SmallWebRTCTransport` in `products/voice-agent/apps/edge/bot.py`. It uses Pipecat OpenAI-compatible STT and TTS adapters against the bearer-protected native broker, and an OpenAI-compatible dialogue adapter against the broker `/pi` path. The broker forwards to the Pi voice service; the Pi service binds selected conversation and turn decisions to the Grain bridge. Preserve `effect@3.22.4` in the TypeScript bridge and attachment path. The pinned Python runtime uses asyncio and httpx; a Python functional library is not a prerequisite for this slice because no new functional rewrite is specified.

Build a protocol driver from the [pinned SmallWebRTC probe](../raw/v1/smallwebrtc_voice.py). Its `aiortc` peer and timed 20 ms PCM frames are a valid physical microphone and browser substitute. The driver must enter via the production signaling route and assert received audio, recognition, Pi/Grain turn identity, and safe public transcript. It must not call STT, Pi, or Grain directly to claim `voice-001`. The existing v1 probe assumes Compose service names, broker token files, and v1 paths; adapt these in the implementation turn rather than copying its deployment assumptions blindly.

## Locally controllable and deployed prerequisites

Local work can supply a protocol peer, synthetic microphone audio, fixed owner identity, ephemeral service secrets, deterministic model protocol outputs, and fresh Grain/Pi data. Such a run qualifies the route, identity, timing, and persistence it actually exercises. A fake transcription or speech server must be labeled a provider substitution and cannot qualify native MLX speech.

Deployed media qualification needs an Apple Silicon host, the locked Python/Node environments, live Parakeet and Kokoro model assets, a working Pi model credential/provider, owner ingress and exact owner mapping, the native broker and Pi voice service, and a reachable public edge. The pinned [host requirements](../raw/v1/host-requirements.md) and [environment example](../raw/v1/voice-env.example) are v1 setup evidence, not a v2 deployment script. V2 currently has no complete host service installer, public ingress deployment, or model provisioning path. Persistent voice VM qualification additionally requires built Gondolin assets and its configured image path, permitted workspace, and successful actual VM boot. Durable task qualification separately requires a deployed owner/worker and an eligible task with a real socket and result. Do not infer either from the local task socket driver in slice 04.

2. Bring up fresh Grain, Pi, broker, and edge processes with explicit loopback boundaries. Run `voice-001` through `voice-006` with a live protocol peer. Capture signaling status, RTP input/output, recognized text, one turn identity and destination, and a post-restart public read.

Capture the provider versions, owner-safe correlation IDs, response audio evidence, transcript, and result. The evidence report must name the precise entry and provider substitutions. A service configuration check, Python import, direct HTTP chat test, or healthy model endpoint alone cannot mark the deployed voice journey complete. Avoid recording tokens, raw private audio, or full private tool output in committed evidence.

## Build invocation update, 2026-11-07

The build added [a media qualification driver](qualification/voice_media.py), [named tests](qualification/test_voice_media.py), [a gated runner](../harness/qualify-voice.sh), and a [variable template](qualification/voice-stack.env.example). Before implementation, `voice-001` through `voice-006` all failed because `voice_media` was absent. The driver now uses a real `aiortc` offer and timed RTP input. It checks audible response media and selected public history for `voice-001`, compares the selection with the v2 Grain bridge to reject a v1-only deployment, supports an explicit service restart for `voice-002`, and rejects foreign-owner reads and signaling for `voice-006`. The edge now requests Pi abort on peer disconnect. None of these are a fresh deployed pass.

The immediate bootstrap order is: create separate persistent tasking/session/Pi session directories; start the Grain bridge from `impl/` with its token and loopback port; build the TypeScript workspace; supply actual Gondolin image, workspace, Gitea, artifact, Wassette, Grafana, model, and Pi credentials; start the Pi voice service with the Grain URL/token and exact owner; start the native broker with matching bearer and owner; start the Pipecat edge with the broker and gateway URLs and a protected owner ingress; then run `harness/qualify-voice.sh` with explicit v2 Grain URL/token. The [variable template](qualification/voice-stack.env.example) lists the environment contract. Provisioning these external assets and ingress is not automated in v2 yet. The host's current `:9443` and `:9446` listeners are v1 services and cannot satisfy this gate because their selection is not bound to the v2 Grain bridge.

`voice-003` still needs a controlled streaming disconnect plus an inspectable turn identity and outcome. `voice-004` needs an eligible deployed task and task-side proof that its conversation received the spoken prompt; a local socket driver is insufficient. `voice-005` needs an isolated provider outage so production services are not disrupted. These named tests remain red by design until those facilities are built. Full slice qualification and the actual Gondolin/worker checks remain open.

## Isolated v2 media run, 2026-11-07

An isolated launcher now starts actual v2 Grain, Pi, native broker, and Pipecat edge from this repository on loopback ports `9547`, `9546`, `9543`, and `7861`. It uses separate fresh directories under `/tmp/awp-v2-media-stack-slice05`, ephemeral service tokens, the owner's host model configuration, and a direct broker-to-Pi readiness check. The v1 services on `9443` and `9446` remain outside this path. The qualification driver compares the public active session with v2 Grain before each scenario. The launcher sets a private diagnostics directory because the production default `/var/lib/voice-diagnostics` is not writable by a local process, and limits ICE host candidates to loopback for same-host peers. The latter setting does not apply to deployment.

Focused runs passed `voice-001` (real `aiortc` offer and 20 ms RTP microphone frames, Pipecat media, Parakeet STT, Pi/Grain selected history, Kokoro response audio), `voice-002` (fresh audio turn, Pi process restart, same public history and Grain selection after resume), and `voice-006` (foreign-owner history and signaling rejected). The Pi service created a Gondolin voice session at readiness, so local boot succeeded with the configured host assets. These runs do not prove public tailnet ingress, exact dispatch count, spoken waveform equivalence to the saved answer, VM survival across host restart, or a deployed task worker. The remaining `voice-003`, `voice-004`, and `voice-005` methods still fail with their explicit prerequisites, so the full named gate is not green.

To close the deployment gap, provision a v2 service instance with persistent Grain/Pi/task storage and protected owner ingress, expose a reachable ICE path, and use independent host service supervision rather than the foreground local launcher. Run the full gate against that instance with an explicit v2 Grain URL/token and fresh conversation. Add a turn identity/outcome read for controlled disconnect, task-side evidence from a real eligible worker, and scoped speech-provider outage injection. Re-run all six named scenarios and retain redacted correlation IDs, provider versions, response-media counts, and public history hashes. Do not use the host's v1 listeners as qualification evidence.
