# Operational incidents implementation notes

Cites [slice 11 plan](../docs/plan/11-operational-incidents/plan.md), [incident scenarios](../docs/plan/11-operational-incidents/spec.feature), and the [pinned monitor](../raw/v1/stack-alert-monitor.py).

Use Grain as the authoritative incident command/event store. The poll adapter reads Grafana's alert API and the approved `stack-alerts.json` inventory; it submits validated observations as commands. Preserve the source monitor's one-minute cadence and 30-minute cooldown. The adapter obtains bounded Prometheus evidence, using the source's finite-sample and safe-label limits. The incident command records request intent before submitting to the existing Grain task admission path. This boundary is implemented in Clojure; the existing TypeScript clients use Effect. Retrying after an uncertain acknowledgement must use exactly the same canonical task input. A separate query projection joins Grain incident decisions with Grain task state. Include a rebuild/restart probe and owner-scoped query routes. The investigator remains Pi Durable read-only execution. A deterministic monitor double is the acceptance baseline; live Grafana/Prometheus and real investigator output need separate qualification.
