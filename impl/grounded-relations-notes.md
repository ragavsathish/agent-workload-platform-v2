## Current seam

`knowledge/taxonomy-relation!` accepts `:broader` or `:related`, requires both endpoint proposals accepted in the same owner state, checks an exact excerpt in the source, and stages `:pending`. `taxonomy-relation-review!` accepts, rejects, or revokes with revision checks and refuses broader cycles. `taxonomy-relations` filters for accepted relations and accepted endpoints. `orc_adapter.clj` projects accepted relations into the owner ontology with `skos:broader` and `skos:related`. Its public owner search/traverse/export intersect with Grain state, so retained ORC history does not itself publish a relation. The bounded ORC LLM path currently extracts up to two concepts, not relations. The quality runner returns relation evaluation unavailable.

ORC's general exploration sheet has hierarchy and related-discovery nodes, plus causal links. Its output is label-based and lacks an AWP owner source excerpt per edge. Reuse its behavior-tree method, but design a bounded relation sheet whose input is accepted endpoint IDs, labels, and exact owner source; output must use IDs and exact edge excerpt. Keep deterministic validation and persistence outside the LLM node. The ORC relationship command supports `skos:broader` and `skos:related`, idempotent command IDs, and cycle refusal. It cannot replace Grain owner review authority. The full text ontology builder previously timed out locally; the bounded sheet has already worked for concept smoke.

Keep the source excerpt and model trace on a candidate and in Grain pending history. Bind a result digest to the complete attempt and candidate payload; retries must not let a changed model response overwrite an existing result. A correction can use a new linked relation ID, reject the original pending one and stage the owner replacement, then require a separate accept. Add a relation-attempt status query if needed for empty, invalid, timeout, or failed runs. Avoid ORC direct owner exposure and ensure all graph reads are Grain-filtered. Validate the source supports the edge semantically in reviewed quality cases; exact substring alone cannot do this.

Start the build with red named acceptance checks for `relation-001` through `relation-012`. Run a safe bounded live-model example, report model/prompt/trace and elapsed time, and leave semantic quality open until eligible reviewed relation cases exist. Run documentation hashes, `allium check specs`, the relevant Grain tests, runtime checks, full verifier, restart probe, and fresh fence after green. Public and private reports must not include owner source text.
