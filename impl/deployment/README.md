# Slice 06 deployment runbook

Cites the [slice 06 plan](../../docs/plan/06-public-deployment/plan.md), [pinned host contract](../../raw/v1/host-requirements.md), and [implementation topology](../public-deployment-notes.md).

This is a single-owner macOS deployment. The native supervisor owns the Grain bridge, Pi voice service, broker, task gateway, and independent task scheduler. The public Compose namespace owns Tailscale, the identity proxy, and Pipecat edge. It does not publish a host or LAN port. The Grain event store and session directories live under a private state directory outside the checkout.

## Prepare

1. Install the v1 [host prerequisites](../../raw/v1/host-requirements.md), including Docker Desktop, Clojure, Node/pnpm, uv, Pi credentials, models, and Gondolin assets. `pnpm --dir impl/runtime install --frozen-lockfile` then `pnpm --dir impl/runtime run build`; run `uv sync --frozen --no-dev` in the broker and edge directories.
2. Copy [service.env.example](service.env.example) to an outside-checkout private file, fill real paths, tokens, owner, and workspace mapping, then `chmod 600` it. The native supervisor reads this file and passes it to its children. Keep its parent directory private. Copy [edge.env.example](edge.env.example) to a different 0600 file; give it only edge capabilities. Do not reuse the Grain token in the edge file.
3. Start the supervisor with `python3 impl/deployment/stack.py run --env /private/service.env --state /private/awp-v2-state`. For boot persistence, run `python3 impl/deployment/stack.py install --env /private/service.env --state /private/awp-v2-state`, then `launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.awp.v2.owner-stack.plist`. The checkout path in the installed service must remain valid. Check `python3 impl/deployment/stack.py check-ready --env /private/service.env --state /private/awp-v2-state` before exposing public entry.
4. Set `AWP_PUBLIC_EDGE_ENV=/private/edge.env` and run `docker compose -f impl/deployment/compose.yml up -d --build`. In the Tailscale container, authenticate with `docker compose -f impl/deployment/compose.yml exec tailscale tailscale --socket=/tmp/tailscaled.sock up`. Verify its logged-in identity and MagicDNS name. Configure a tailnet policy allowing the owner device alone to reach this node on TCP 443, based on [the pinned example](../../raw/v1/tailnet-policy.hujson.example). Then run `docker compose -f impl/deployment/compose.yml exec tailscale tailscale --socket=/tmp/tailscaled.sock serve --bg --https=443 http://127.0.0.1:8080`. Set `PIPECAT_ALLOWED_ORIGINS` in edge.env to the exact resulting HTTPS origin and `EDGE_ALLOWED_USERS` to the exact owner login; recreate edge after changing that file.
5. Check the public owner route from another tailnet device. The identity proxy routes only authenticated owner traffic. A 200 response to `/api/features` is a routing check; it is not a voice qualification. The broker and gateway stay on host loopback; no task authority or Grain port has a public route.

## Task scheduling and recovery

The optional incident poller is enabled by `AWP_INCIDENT_RULES_FILE` and the related values in [service.env.example](service.env.example). Point the rule file at a pinned, reviewed copy of [the source inventory](../../raw/v1/stack-alerts.json). Create an empty private `scratch` workspace with no repository grants or network policy, map it in `AWP_WORKSPACE_MAP_JSON`, and make it eligible. The poller reads the loopback alert and metric APIs every 60 seconds. It stores owner incident decisions in the Grain incident event store, submits one immutable request per epoch to Grain tasking, and exposes owner-scoped incident history at `GET /v1/incidents?identity=<owner>` and `GET /v1/incidents/<epoch-id>?identity=<owner>` through the authenticated gateway. The scheduler runs accepted investigations inside that isolated scratch workspace. Recheck actual alert delivery and metric meaning in the deployed host; the deterministic checks do not certify those external sources or the investigator's conclusions.

`AWP_ELIGIBLE_WORKSPACES` lists logical names Grain may accept. `AWP_WORKSPACE_MAP_JSON` maps each name to a real, prepared, private host workspace for the Gondolin worker. The scheduler polls Grain, claims pending tasks, dispatches one attempt, and starts `scheduled-worker.js`. It never runs a task until Grain confirms dispatch. A lost running worker is marked interrupted and requires an explicit owner retry at `/api/tasks/<task-id>/retry`. A successful retry clears the recovery flag in Grain; the scheduler then releases its private interrupted claim and starts one new attempt. The private claims ledger prevents blind rescheduling after a scheduler restart. Inspect task state through the owner route; the scheduler does not expose a public operator API.

For task delivery, the scheduler clones the selected repository revision or creates an empty scratch workspace under `AWP_TASK_WORKSPACE_DIR/<task-id>/workspace` before dispatch. Grain records the revision and captures only that task workspace. Repository patch capture uses a temporary Git index, leaving the selected checkout's index intact. Worker logs stay under `AWP_TASK_WORKER_LOG_DIR` with private permissions. A repository image declaration needs a verified, existing image path in `AWP_TASK_IMAGE_MAP_JSON`, keyed as `<declared-image>@<source-revision>`; missing handoff fails the task before the VM starts. Host mode bypasses image preparation. External image building and registry qualification require their own configured services.

A service restart changes process IDs while the state directory stays fixed. `stack.py status` reports supervised PIDs; `stack.py check-ready` calls actual health/authority endpoints. Stop with `launchctl bootout gui/$(id -u) ~/Library/LaunchAgents/com.awp.v2.owner-stack.plist` or stop the foreground supervisor. Keep the state directory when updating binaries. Take a compatible state backup before a release. Keep immutable release checkouts under `/private/releases/<version>` and a `/private/current` symlink. Invoke `stack.py install` through `/private/current/impl/deployment/stack.py` so the installed service follows that link. Register the last passing release with `stack.py qualify-version --state /private/awp-v2-state --current-link /private/current --version <version> --release /private/releases/<version>`. To stage a candidate, use `activate-version` with its path, restart the LaunchAgent with `launchctl kickstart -k gui/$(id -u)/com.awp.v2.owner-stack`, and run readiness plus the public journey. On failure, `stack.py rollback --state /private/awp-v2-state --current-link /private/current` atomically switches the link to the prior qualified release; kickstart the LaunchAgent and recreate the public edge image from that release, then rerun the owner and task checks. State stays outside release directories. Before switching, confirm the previous binary can read the current state schema; this build has no automatic data downgrade.

## Qualification gates

The nine named control-plane checks run with `python3 -m unittest discover -s impl/deployment -p test_deployment.py -v`. The six real local media scenarios run via [the isolated launcher](../qualification/README.md). The separate-device public media gate is `impl/runtime/products/voice-agent/apps/edge/.venv/bin/python impl/deployment/qualify_public.py --origin https://<exact-magicdns> --owner <owner-login> --audio-wav /private/utterance.wav --report /private/public-report.json`; it requires the Tailscale CLI on a **different** connected device. Transfer this probe and its locked environment to that device if necessary. It sends no forged identity header, records the nominated ICE pair and audible media, and compares the new public selected turn. Copy the resulting report to the host, then run `impl/runtime/products/voice-agent/apps/edge/.venv/bin/python impl/deployment/confirm_public_report.py --report /private/public-report.json --grain-url http://127.0.0.1:9447 --grain-token-file /private/grain-token --owner <owner-login>` to compare its turn ID, selected conversation, and answer hash against private v2 Grain. From a foreign tailnet device, run the same probe with `--expect-denied --report /private/foreign-report.json` in place of `--audio-wav`; this attempts a spoofed owner header and requires denial. Pair that report with a successful owner report so an outage is not mistaken for authorization. Run a controlled restart/rollback separately; no same-host result qualifies those gates.

The current host has Docker but no Tailscale CLI or Tailscale.app and no configured v2 public origin. Therefore `deploy-001` through `deploy-004` and external portions of `deploy-005` and `deploy-008` remain unqualified until that setup exists. This runbook does not claim the public gate has passed.
