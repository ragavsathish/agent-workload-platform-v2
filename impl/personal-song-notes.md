# Slice 09 implementation notes

Cites the [slice plan](../docs/plan/09-personal-song/plan.md), [song contract](../docs/wiki/personal-song.md), and [formal model](../specs/personal-song.allium).

## Authority and interface

Implement the song aggregate and approval decisions in Grain CQRS, beside the existing task and session streams. Commands are `CreateSong`, `DecideSongManifest`, `RequestSongRender`, and `CancelSong`; owner queries are `GetSong` and `GetSongAudio`. The command gateway authenticates identity and normalizes request input. A generation ID comes from the accepted creation request; lyric and render task IDs derive deterministically from that generation ID. Persist a request ledger keyed by owner and request ID with an input digest. Event names are `SongRequested`, `LyricsPrepared`, `LyricsFailed`, `SongManifestApproved`, `SongManifestRejected`, `SongRenderRequested`, `SongStored`, `SongRenderFailed`, and `SongCancelled`. The read projection returns bounded status, exact manifest and digest, task IDs, approval status, artifact ID or owner-checked audio route, and safe failure text.

Use the existing task authority for lyric and render tasks, with a persisted outbox or equivalent handoff that can reconcile a crash after command acceptance. Effects run through Effect TypeScript workers. Lyric work uses a Pi Durable agent task in an eligible workspace; render work passes the approved manifest to the loopback ACE-Step adapter, converts its output to bounded M4A, and writes the artifact. The worker returns only an opaque artifact reference. Keep model output, raw audio, private text, and direct artifact URLs out of task progress and telemetry. The gateway should follow the existing authenticated owner route used by v1, while v2 command and query shapes follow the Grain service boundary.

Validate the manifest before emitting `LyricsPrepared`: title at most 200 characters, style at most 1,000, lyric text at most 20,000 with section markers, duration 30–300 seconds, tempo 40–200, a bounded key/scale, and meter 3, 4, or 6. Use a canonical serialization and digest for review. The `DecideSongManifest` command accepts exact digest and stable decision ID; the render command reads recorded approval from Grain, not a request boolean. Rejection and changed lyrics require a new generation. Keep one render task per generation even after failure. Cancellation prevents late audio publication in the read model and should abort active task work where supported.

## Evidence and prerequisites

Deterministic acceptance uses synthetic owner data and a protocol double at the lyric and render effect boundary. Production qualification needs a reachable ACE-Step service with initialized models, the configured media conversion tool, artifact storage, and an authenticated owner path. Listen to the delivered complete audio and inspect format, duration, and accessibility before claiming deployed quality. The private tailnet/public deployment gate from slice 06 remains open. The old knowledge cutover from slice 08 is unrelated and remains open. The v1 manual PR soundtrack guide is source context only; no PR editing or soundtrack publishing belongs to slice 09.

## Built slice

The Grain song stream is the authority for request identity, immutable manifest, owner decision, render admission, outcome, and cancellation. The public gateway exposes `/v1/music/generations` with create, read, approve or reject, render, cancel, and owner-checked audio. The loopback Grain bridge has matching `/internal/song` operations. Lyric submission uses the configured Pi Durable owner, and status reads reconcile its native lyric result. The Effect TypeScript worker performs the separate render through ACE-Step, FFmpeg, and a private local M4A artifact directory. The local artifact ID is the generation UUID; the public response contains only the owner-checked playback path. The bridge leaves lyric submission pending if Pi Durable configuration is absent and render submission pending if the worker bundle is absent. No public PR soundtrack automation was added.

The synthetic real-host render result and its technical limits are in the [qualification report](qualification/song-render-report.md). Subjective listening, intelligible lyrics, and the external tailnet owner route still need a deployed owner journey. On bridge restart, a submitted render that has no recorded outcome becomes a failed generation; the owner can start a new generation and review it again. A child renderer that outlives the bridge can leave an unreferenced local artifact, which needs operator cleanup. Do not treat the deterministic acceptance suite as a substitute for the deployed journey.
