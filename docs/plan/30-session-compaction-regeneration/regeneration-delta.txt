# Slice 29 clean-room regeneration delta

This independent build was derived from the Slice 29 plan, scenarios, decisions, session wiki, Allium contract, permitted pinned v1 evidence, and pinned ORC Grain examples. No original `impl/`, prior implementation commit, or agent summary was consulted. Durable source docs were not modified.

## Reconstructed

- `impl/src/awp_v2/session/compaction.clj` implements the pure command admission/reconciliation rules and safe owner context projection.
- `impl/src/awp_v2/session/grain_commands.clj` adds Grain `defcommand` handlers for durable pending, settled, and uncertain facts. It uses ORC's `->event`, `es/read`, flattened event-field, and `:command-result/cas` patterns. Command and owner tags distinguish retries and serialize admission through an append-time owner CAS.
- `impl/src/awp_v2/session/grain_queries.clj` adds an owner-scoped `defquery` returning only command identity, conversation identity, and status.
- `impl/runtime/session-compaction.ts` is a TypeScript Effect workflow over Grain and Pi ports. It persists intent before Pi, invokes `compact()` only for newly accepted intent, and reconciles retries against the stored leaf and count without invoking Pi again.
- `impl/test/awp_v2/session/compaction_test.clj` covers refusal, retry, settlement, uncertainty, owner visibility, and locking. `impl/runtime/session-compaction.test.ts` covers settlement and ambiguity/no-repeat behavior.
- Pinned v1 evidence confirms `SessionManager.getBranch()`, branch entry `type`, `AgentSession.compact()`, the `canCompact` guard (token threshold, not currently compacting, existing leaf not already compaction), and current context route/method names.

## Remaining limits and assumptions

1. **Fenced-room scope versus current v2.** The clean-room fence intentionally removed `impl/` and its dependency setup, so this independent reconstruction could not compile Grain handlers or inspect the executable AWP bootstrap. The current v2 source does contain Grain SQLite event-store/LMDB startup, schema and event-model registration, command/query/read-model loading, event-model validation, and owner projection recovery in `impl/src/awp_v2/session/api.clj`. The public session API routes mutations and reads through Grain command/query processors. Existing acceptance tests prove close/reopen recovery; Slice 31 adds an explicit scenario covering owner projection rebuild and ephemeral recovery. The clean-room reconstruction therefore does not itself establish bootstrap completeness, but the bootstrap is not absent from the current v2 repository.
2. **Trusted admission and shared mutation lock in the fenced
   reconstruction.** Its reconstructed command handler accepts selected,
   eligibility, and busy facts as inputs because the permitted docs did not
   specify the session read-model API or common mutation boundary. Current v2
   reads `:session/state` through `rmp/project` in
   [`read_models.clj`](../../../impl/src/awp_v2/session/read_models.clj),
   obtains the owner projection, checks the trusted `actor-id` against the
   command owner, and derives selection, eligibility, busy state, and
   attachment from that projection in
   [`commands.clj`](../../../impl/src/awp_v2/session/commands.clj). Appended
   facts carry an owner tag and compare-and-swap against the projected event
   revision. Session acceptance coverage checks mutation exclusion while
   compaction is pending and cross-owner isolation. Slice 32 maps this current
   implementation evidence; reconstructing those seams from durable inputs
   remains an open documentation gap.
3. **Pi branch proof in the fenced reconstruction.** The permitted v1 source
   confirms branch inspection and the compaction call, but did not include
   current v2's Pi package declaration. Therefore the clean-room agent could
   not verify the types against the installed package or prove snapshot
   semantics. Current v2 pins Pi 1.2.0; its declarations and live protocol test
   verify the `id`, `parentId`, `type === "compaction"`, baseline leaf, and
   entry-count checks. These observations do not establish an atomic snapshot.
   See [Slice 32](../32-compaction-protocol-reconstruction/plan.md).
4. **HTTP/client integration in the fenced reconstruction.** The permitted
   pinned v1 client evidence does not establish the current v2 idempotency
   protocol, so the independent reconstruction could not derive its exact
   fields and recovery behavior. Current v2 implements and tests the public
   `GET /api/pi-context` and `POST /api/pi-context/compact` routes, forwards
   `x-awp-command-id`, and restores queued/pending/uncertain IDs from Grain
   context after page reload. The current contract and test mapping are in
   [Slice 32](../32-compaction-protocol-reconstruction/plan.md).
5. **Uncertain resolution.** Slice 33 now specifies and implements the current-v2 contract: restart or an unproven Pi call becomes owner-visible uncertainty; the lock remains held; a same-ID retry may settle only from the exact persisted Pi branch proof and never claims another Pi effect. With no distributed fencing token or proof that the old Pi writer has stopped, no owner/admin release is safe, so an unproven command remains held indefinitely. This closes the behavior-spec gap while preserving the runtime limitation that no safe override exists. See [Slice 33](../33-compaction-uncertainty/plan.md).

## Remaining reconstruction limits

The clean-room reconstruction still cannot recover the trusted owner key
contract or shared owner lock integration from permitted sources, nor establish

proof-only settlement, and terminal hold are documented and test-mapped in

## Slice 32 disposition

Current v2 pins `@earendil-works/pi-coding-agent` 1.2.0 and uses its session
branch/entry declarations in the compaction proof. The runtime protocol test
reopens the persisted Pi session after Grain settlement loss, checks the
compaction entry's `type` and `parentId`, and proves reconciliation does not
invoke Pi a second time. The Flutter client retries with the same command ID
and recovers it after reload from owner context. The precise contract and test
mapping are recorded in Slice 32. These current-v2 facts were not derivable
from the clean-room input set, which intentionally removed the runtime code,
dependency declarations, and Flutter client.

Current v2 also reads compaction admission state from the owner projection and
serializes event append through the owner tag and compare-and-swap predicate;
the fenced reconstruction's caller-supplied admission values are not a
description of the implementation. This evidence is mapped in Slice 32, but
the durable rules still need to be detailed enough for an independent rebuild.

## Slice 33 disposition

The current v2 Grain projection records a bounded uncertainty reason while
retaining the owner mutation lock. Startup marks pending compaction uncertain
before accepting commands. Same-ID retry reads the saved baseline for both
pending and uncertain states; it can settle only when the Pi branch has the
expected tail compaction entry parented to that baseline with a higher entry
count. Otherwise retry does not claim or invoke another Pi compaction. The live
protocol test covers a failed call with no proof, a no-effect retry, and a
later persisted matching proof without a second `session.compact()` call.

This is an indefinite terminal hold when no proof arrives, not a recovery
mechanism that releases the lock. The inspected AWP process-local operation
queue and Grain owner append CAS do not fence a Pi effect across concurrent
processes. Until deployment supplies a verifiable writer fence/termination
proof, owner/admin release remains intentionally unavailable.
