## Source port and dependencies

The runtime source is ported from AWP v1 commit `d8afdfc31ea3ac7d74eef625c8863f5954b75fcd`. The retained production subset is `products/voice-agent/apps/edge` (Pipecat SmallWebRTC, STT, TTS, owner routes), `products/voice-agent/apps/broker/src` (bounded inference and Pi forwarding), `products/voice-agent/apps/pi-agent/voice-agent` and its service entry point (Pi session, public HTTP routes, task socket), `platform/agent-execution/gondolin-session` (`session.ts`, `gondolin-operations.ts`, and runtime prompts), `platform/observability/otel`, and the voice telemetry package. Their v1 package layout and Python lockfiles remain intact. Gondolin image-builder, task-worker extension, benchmarks, development images, generated `dist`, and unrelated tests are excluded from this live owner slice. The deployed Gondolin image is still an external asset supplied by `GONDOLIN_ASSETS`.

The TypeScript workspace pins `effect@3.22.4`; the new Grain HTTP client uses `Effect.gen` and `Effect.tryPromise`, and task attachment uses an Effect program to release the remote socket if Grain refuses the attachment. Other imported Pi runtime files remain close to the pinned v1 source. Python edge and broker use their pinned `uv.lock` environments and asyncio/httpx for protocol lifetimes.

The edge `Containerfile` builds the voice API from the retained source tree. The v1 Flutter client, diagnostics UI, and knowledge UI build outputs are outside this slice, so their former `COPY` directives were removed; those owner UI assets require their own port before a complete product image is available.

## Runtime binding

`awp-v2.live.main` starts the durable task and session systems plus a loopback-only, bearer-protected Grain HTTP bridge. The Pi service requires `AWP_GRAIN_SESSION_URL`, `AWP_GRAIN_SESSION_TOKEN`, and `AWP_OWNER_IDENTITY`, and forwards the latter identity to Grain. The broker uses that fixed owner identity plus the service bearer when forwarding `/v1/pi/*` requests. The edge retains the `/api/pi-*` owner contract and requires Pi as the live LLM backend. A stable typed idempotency key or voice turn identity reaches Grain through the broker and Pi service.

Grain selects and admits turns; Pi executes the chosen conversation; its safe text, tool, and context observations return to Grain before settlement. The public catalog, history, transcript, and context read Grain projections. An existing selected Grain conversation with saved content fails closed if its Pi session file is absent. Completed turn retries return the recorded answer without another Pi prompt. Accepted or uncertain retries refuse dispatch. A stopped turn remains uncertain if Pi later produces output. Fresh and resume release temporary task routing while preserving the service-owned Gondolin instance. The task socket remains the execution destination for attached task turns; its conversation is not copied into the voice history. Graceful voice shutdown and subsequent startup clear a stale attachment.

## Verification and limits

`./harness/verify.sh` checks locked docs and raw hashes, Allium, all Clojure acceptance and strict Grain composition tests, TypeScript build, the real Pi HTTP and Grain-process protocol journey, broker ASGI forwarding, Pipecat module import, and existing public probes. The nine named `live-001` through `live-009` Clojure tests cover the bridge decisions. The Node journey uses the production Pi `ModelRuntime`, `SessionManager`, `VoiceAgent`, HTTP route handler, a live Grain process with restart, a deterministic OpenAI-compatible outer model protocol server, and a real Unix socket protocol for a seeded durable task. It verifies single dispatch on completed retry, refusal of an uncertain retry, typed and streamed turns, task routing, fresh/resume, bounded invalid input, credentials, interruption outcome, and selected history. The broker ASGI test checks owner, turn, origin, and selection-command headers through its production route handlers.

The verification environment has no deployed WebRTC signaling peer, audio device, MLX STT/TTS models, or configured Gondolin image. Therefore a spoken *media* turn through an actual Pipecat live connection, a production Gondolin VM boot, and the deployed durable task worker remain unverified. The Node journey exercises the streaming voice HTTP protocol with a model driver and a task socket driver, not an audio connection. Provider compaction is not exercised; the public route refuses it until observed context says it is eligible, and a successful Pi compaction then records estimated usage in Grain. A process failure between Pi compaction and its Grain fact can leave recorded usage stale. A process failure after Grain accepts a turn and before settlement leaves it inspectable as accepted; retry refuses another external prompt rather than reconstructing the missing outcome. These are explicit reconciliation limits for the next slice or deployed qualification gate.
