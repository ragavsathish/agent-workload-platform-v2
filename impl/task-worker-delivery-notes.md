# Slice 13 task worker delivery evidence

Cites [slice plan](../docs/plan/13-task-worker-delivery/plan.md), [pinned v1 workspace effect](../raw/v1/task-workspace-effect.py), [pinned image resolver](../raw/v1/task-image-ensure.py), and [formal contract](../specs/task-worker-delivery.allium).

The scheduler now prepares one task-specific directory before dispatch and passes that path, pinned source revision, optional resolved image, and selected repository grant to the scheduled Pi worker. Grain's dispatch event records the source revision. Its capture callback reads the matching task directory and source marker, then records only the bounded result and artifact descriptor. The owner route presents the revision, safe answer, and declared download. The worker posts `task-id` to Grain for progress, completion and failure; the earlier camel-case key left real tasks running without settlement. Progress posts drain before completion. Worker spawn failures settle the same task with a bounded reason, and a private worker log retains diagnostics.

The local controlled-process public-path suite exercised scheduler dispatch, Grain capture, repository patch and scratch ZIP, a fresh Grain and gateway process, foreign-owner denial, oversized capture failure, duplicate/late callback refusal, and source isolation. Repository capture now uses a temporary Git index; a Clojure test checks the index bytes are unchanged and the patch still includes a new file.

An actual scheduled Pi host task completed with answer `Done.` and owner archive download of 146 bytes. An actual scheduled Pi Gondolin scratch task completed with answer `Done.`; its owner archive contained `note.txt` with exact text `isolated slice thirteen`. An actual scheduled Pi Gondolin repository task completed with answer `Done.`; the owner patch contained `isolated repository slice thirteen` and the selected source checkout remained unchanged. A second real Gondolin repository run used a repository-declared image resolved through the trusted local map; it completed, its owner patch contained `declared image handoff`, and the source checkout remained unchanged. All runs used a local authenticated Pi model and the isolated runs used the local aarch64 Gondolin browser image. These are local process qualifications, not external tailnet, separate-device, repository publication, Gitea push, or image build qualification.

Conditional repository image handoff currently accepts a preinstalled image path from a trusted deployment map keyed to the declared image and source revision. Missing or mismatched handoff fails before VM startup. The external build and installer workflow from v1 has not been reproduced or qualified here. A repository with a declared Gitea write grant receives its matching repository identity, but an actual Gitea token/route/push was not exercised in this slice.
