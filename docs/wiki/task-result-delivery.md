# Task result delivery

Cites [the pinned v1 inventory](../../raw/v1/manifest.md), [C2 task contract](../../raw/v1/c2-tasking.feature), [task service](../../raw/v1/task-service.py), [artifact store](../../raw/v1/task-artifacts.py), [workspace effect](../../raw/v1/task-workspace-effect.py), [owner gateway](../../raw/v1/gateway-main.py), [owner client](../../raw/v1/client-workspace.dart), and [task lifecycle](task-lifecycle.md).

An **Agent Task** owns a bounded answer and, when captured, one downloadable work product. The answer is a projection of the execution response: text, spoken summary, presentation, and optional resource reference. It is inspectable through the owner task query. A completed task can still have an unavailable artifact; that lookup failure does not change the task's terminal outcome. [C2-001, C2-005]

The work product kind follows the selected workspace. A repository task yields a patch of its changes. A repository-free scratch task yields a workspace archive. The source captures a bounded patch or bounded regular files, skips links in scratch, and refuses escape and size violations. Capture failure is an execution failure, so no completion may claim a downloadable artifact it failed to capture. A successful result names only the artifact kinds that were captured. The private storage address and raw execution record do not appear in the public answer. [Workspace effect, artifact store, gateway]

The owner can ask for the declared artifact by task identity and kind. The read first checks task ownership and selected workspace kind, then checks that the task result declares the exact object for that task, then reads only a bounded known object. A wrong owner receives the same missing-task answer as an unknown task. An absent, mismatched, oversized, or incomplete object produces an explicit retrieval failure. The client offers a download only when the task result advertises the expected kind. [Task service, artifact store, service tests, owner client]

The selected repository's input is an immutable, approved source snapshot. Publishing and resolving that source are separate from task result retrieval. A task may prepare that snapshot for execution, but the task's result remains tied to its own identity and selected workspace. This slice covers that source handoff only as needed to prove repository task output, and does not make image preparation or repository publishing a new user workflow. [Task artifact store, workspace effect, C8 execution contract]

The [slice 12 plan](../plan/12-task-result-delivery/plan.md) closes the gap left by [slice 02](../plan/02-task-lifecycle/plan.md): v2 currently records an arbitrary terminal result and exposes task state, but does not capture, declare, or serve the corresponding bounded patch or scratch archive through an owner query.
