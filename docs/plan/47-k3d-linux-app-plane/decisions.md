# Slice 47 decisions

1. **Use ClusterIP for all app-plane services.** Temporary loopback port-forwards are qualification tools only. No AWP Ingress, NodePort, LoadBalancer, public route, or tailnet route is introduced.
2. **Keep Flutter as the owner UI.** It remains bundled with the Pipecat Edge service; Semaphore is the operator/deployment UI.
3. **Keep native Pi, MLX, Gondolin, and trace-explainer processes host-managed through Semaphore.** The host trace-explainer MCP remains an unqualified Edge dependency until its network path from k3d is proven.
4. **Keep Edge identity checks enabled.** Do not enable local-ingress bypass to make internal probes pass. Authenticated broker health and authenticated Grafana MCP operations are component evidence, not proof of a complete owner session/voice flow.
5. **Keep Grafana MCP scoped to v2.** Use a dedicated viewer service account and Kubernetes Secrets; do not record token values.
6. **Use the active broker credential only for its source-confirmed broker API.** Extract only `INFERENCE_BROKER_TOKEN` from the dotenvx-managed host broker file; do not modify the host file or log the value. Port 9443 is the broker route. Port 9743 was only an unverified TCP connect and is not broker evidence.
7. **Deploy MLflow in k3d.** It was an active v1 Compose workload from the MLflow override. Keep its SQLite state on a PVC and proxy artifacts to the v2 S3Mock endpoint.
8. **Defer a Fluent Bit DaemonSet as a separate metrics translation, not as an omitted app dependency.** The active v1 Compose config uses Fluent Bit's `node_exporter_metrics` input against read-only `/host/proc` and `/host/sys`, then exposes aggregate Docker Desktop VM CPU, memory, load, disk, and network metrics labeled `system=docker-desktop-vm,layer=vm`. It does not collect pod logs. These host VM metrics are not part of the owner voice/task flow, and a k3d-node collector would describe a different system; deploying one in this slice would not preserve the source signal. Current v2 app health uses Kubernetes readiness and service-originated OTEL metrics, while CRI logs remain available through Kubernetes. A separate slice will decide whether to introduce explicit k3d-node metrics and how Semaphore manages the host metrics collector. Do not mount macOS or Docker Desktop VM procfs/sysfs into app pods and do not claim parity.
9. **Exclude the Caddy Gitea ingress helper, Tailscale, and Traefik from this app-plane slice.** Gitea remains internal ClusterIP and no route has passed an external qualification gate.
10. **Stop v1 only after v2 component qualification.** The parent orchestration stopped all 13 Compose containers without deleting named volumes; the v1 project filter is now empty. Do not treat v1 runtime or Prometheus as v2 evidence.
